## Overall goal

Prepare a coherent, practical introduction to Python and data-science tools for health data science master's students who are beginners in programming. Lectures should explain concepts in order, with visuals, useful reference cards, minimal method examples, and relevant humor. Demos should be reproducible independently after a missed class. Assignments should be doable using preceding lectures and demos, with well-defined student-created artifacts and helpful, generous checks.

Each ordinary class has 90 minutes, aiming for 60 minutes of lecture and 30 minutes of core demo walkthroughs. Reference coverage may exceed what is discussed in depth; extended demo sections are labeled independent practice. Lecture 11 is the project-workflow exception. Successful execution and shorter files do not establish a 90-minute classroom fit.

## Source layout and working paths

- `NN/README.md`: lecture; `NN/BONUS.md`: optional material. AGENTS.md defines the exact opening, headings, captions, topic pattern, and demo-marker format.
- `01–03/demo/DEMO_GUIDE.md`: script-based independent walkthroughs. `04–11/demo/*.md`: authoritative notebook sources; generate paired `.ipynb` files with Jupytext. Each notebook installs its packages and fetches missing non-notebook inputs during setup, preserving existing files. Each local demo folder ships a supplied uv project/lock and `setup_demo.sh`.
- Use Python 3.13 and pandas 3.0.5 for teaching; uv with `pyproject.toml`/`uv.lock` is the default. Notebook Colab setup keeps `%pip`. Graders also support system Python 3.9; this compatibility does not change the teaching version. Never grade a reported Python version.
- `NN/assignment/`: handout; `NN/assignment_checks/`: authoritative course-owned checks. Homework checkers are byte-identical in both locations. Homework is pass/fail with full local feedback; exams 05/11 ship no checker or workflow and have 75 automated plus 25 human-review points. Grade committed artifacts only; never inspect source patterns or execute student code. Accept equivalent formatting/approaches, charge each mistake once, and judge downstream artifacts against the student's own earlier ones.
- Current homework workflow sources fetch the **whole** checker set named by `CHECKS_FILES` from this course's `main`, validate it, and fall back to the vendored set if needed. Older published handouts/forks may have older workflows; do not assume every fork fetches current checks. Change both course-owned and vendored files together and verify emitted JSON, not only the checker's exit status.
- `assignments.json` maps term repositories. `uv run scripts/grade_submissions.py NN` grades collected forks with trusted course checks; `--fork owner/repo` scopes collection. It does not run student code, preserves TA columns, and refuses dirty clones. Live fork collection was not exercised in this review.
- Use ignored repo `scratch/` or `tmp/` for trials. The existing `scratch/py313-demo-env` is shared verification infrastructure: treat it as read-only and create isolated environments for dependency changes. `work/tufte/` holds local reference PDFs, is ignored, and is not for redistribution. Intel Mac local support may remain unavailable where the pinned environment requires it; Colab is the intended alternative.
